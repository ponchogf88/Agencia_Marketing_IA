AMDA · Agencia de Marketing Digital y Automatización

Workflow de agentes de IA

El flujo completo de la agencia operado por agentes: conseguir clientes, vender, entregar el servicio y retener cuentas. Cada tarjeta es un agente con su stack de herramientas; la línea entre tarjetas muestra exactamente qué entrega al siguiente.

16 agentes 5 fases 3 capas de construcción 🟠 = interviene un humano

Con qué se construye cada agente

Todos los agentes se arman con las mismas 3 capas. La tarjeta de cada agente indica su combinación exacta.

Capa 1 · Cerebro

Claude Projects

Un Proyecto de Claude por rol de agente (y uno por cliente). Las instrucciones son el "brief permanente"; la base de conocimiento guarda guías de 1–3 páginas. Para los agentes que corren solos, el mismo brief se usa vía API de Claude dentro de Make.

Claude Pro/TeamClaude API
Capa 2 · Manos

Make + canales

Make ejecuta: escucha disparadores (mensaje nuevo, pago, fecha), llama al cerebro, y mueve el resultado al canal correcto. El CRM en Notion o Airtable es la memoria compartida de todos los agentes.

Metodología Claude Projects aplicada a AMDA

Auditoría honesta del workflow contra las reglas del curso: qué ya cumplía, qué faltaba y cómo se aplica.

CUMPLÍA
Un proyecto por asuntoEl workflow ya separa un agente por función y prohíbe mezclar clientes. Se traduce directo: un Proyecto de Claude por rol (AMDA-Outreach, AMDA-Propuestas…) y un Proyecto por cliente para contenido y estrategia. Nunca un mega-proyecto.
CUMPLÍA
Precisión sobre volumenLa regla de handoffs ("nada avanza sin su entregable, tight y específico") es la misma lógica: documentos de 1–3 páginas por conocimiento, no manuales de 40. La guía de voz de 3 páginas le gana al manual completo.
A MEDIAS
Instrucciones como brief permanenteEl workflow define roles pero no incluía el brief de cada agente. Cada Proyecto necesita la plantilla del curso: ROL / PARA QUÉ ES / CÓMO RESPONDER / QUÉ ASUMIR / NUNCA — incluida la regla de "no preguntes, asume razonable, decláralo y avanza".
FALTABA
Herramientas concretasCierto: la v1 no decía con qué construir cada agente. Corregido — cada tarjeta ahora trae su stack y la sección de arriba define las 3 capas (Claude = cerebro, Make = manos, IA generativa = producción).
FALTABA
Test de retrievalAl crear cada Proyecto (y el de cada cliente nuevo en el onboarding), correr la prueba: "Según la guía de voz del proyecto, ¿cómo abro un post? Cita la guía exacta". Si responde genérico, el archivo no se está leyendo. Es paso obligatorio del Agente 07.
FALTABA
MantenimientoConocimiento viejo = contexto confiadamente equivocado. Se asigna al Agente 0 + humano: revisar instrucciones cada trimestre y reemplazar documentos cuando cambie el posicionamiento, un precio o un alcance.
A MEDIAS
Capas de personalizaciónPreferencias generales tuyas → instrucciones de perfil (una sola vez). Contexto de cada rol o cliente → instrucciones del Proyecto. Ajustes de un solo chat → estilos. No repetir lo universal en cada proyecto.

Reglas del flujo

Las condiciones que hacen que los handoffs funcionen sin supervisión constante.

Nada avanza sin su entregableCada agente arranca solo cuando recibe la salida completa del anterior; si falta algo, la devuelve con la lista de faltantes.
El CRM es la fuente de verdadTodo lead, cliente y proyecto vive en el tablero central con su etapa actual. Los agentes leen y escriben ahí, nunca en canales sueltos.
Todo handoff deja registroQué se entregó, cuándo y a quién. El Orquestador audita esto para detectar cuellos de botella.
El humano aprueba lo irreversiblePrecios fuera de tarifario, contratos, primer contenido de cada cliente, presupuestos de pauta y comunicación de crisis.
